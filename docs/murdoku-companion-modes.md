# Murdoku Companion：上课模式 vs 考试模式

## 这次会话到底是什么

表面上是在解题，实际上是一堂课：

- AI 扮演老师：提出下一步、落子、解释；
- 用户扮演学生：确认、追问、质疑；
- 用户说的“你跳逻辑了”“床占了两行”“旁边要同房间”“你看不到盘面吗”，才是这堂课真正的教学内容。

产品价值不在答案，而在**推理过程可见、可质疑**：notation、盘面状态、一步一条件、理由能被检查。

## 两种模式：差别在“谁掌握主动权”，不在知识

| | 上课模式（Tutor） | 考试模式（Examiner） |
|---|---|---|
| 主动权 | AI 主导 | 学生主导 |
| 学生角色 | 确认 / 提问 / 质疑 | 做题 / 说理由 / 辩护 |
| AI 角色 | 讲解、落子、适配 | 审计、追问、扣住答案 |
| 盘面 | AI 标、AI 落 | 学生标、学生落；AI 观察 |
| 输出 | 下一步 | 对这一步的判定 |
| 主要风险 | 答案泄漏、学生被动 | 答案泄漏、AI 替学生做 |

## 共享底座（只建一次）

1. **盘面读取器**：已落、笔记、X；落子后的自动行/列 X。
2. **规则书**：beside = 四邻且同房间；spans（床可两格）；east of = 任意更右列；exactly one/two；房间不能空；Vin 恰好两人；椅子恰好两把；每行每列一人。
3. **notation 契约**：格子里的字母 = “这个人可能在这格”，不是“这格可能是谁”。
4. **步骤日志**：学生的 claim + 判定 + 当时的盘面快照。
5. **提示阶梯**：nudge → 规则提醒 → 未标记的条件 → 子目标；**永远不给落点**。

## 考试模式怎么跑

### 1. 捕获 claim

- 学生落子/记笔记，并写一句理由；或
- AI 观察到盘面变化，先问：“这一步的理由是什么？”

### 2. 审计四个维度

- **前提**：引用的线索/盘面事实是否真实、是否已在盘面上可见？
- **规则**：谓词是否用对（同房间、spans、exactly-one…）？
- **蕴含**：结论是否被前提强制？所有其他候选是否都排除了？
- **notation**：标记的语义是否唯一、是否与结论一致？

### 3. 判定词表

- `VALID`：前提真、规则对、结论强制。
- `VALID BUT INCOMPLETE`：对，但错过了更强的结论。
- `GAP`：缺一个前提/链接（例如用了“浴室有 G”但盘面没标 G）。
- `INVALID`：规则误用/有反例（例如跨房间的 beside）。
- `UNPROVEN`：不是强制，只是猜对了。

### 4. 回应方式

- 一次只说一个问题；
- 先问、再指、最后才说怎么补；
- 不替学生落子，不报答案；
- 学生坚持错误时，用一个反例或一个未排除的候选来挑战。

### 5. 结束报告

- 有效步数 / 总步数；
- GAP 类型分布（未标记条件、漏排除、规则误用、notation 混用）；
- 提示使用次数；
- 下一次该练什么（例如“同房间 beside”“容量排除”）。

## 从这次会话得到的产品教训

1. **用户是最好的 bug finder**——前提是 AI 把理由摊开。理由必须是一等公民。
2. **自动 X 和 notation 语义是产品功能，不是实现细节**；语义一乱，信任立刻崩。
3. **“一步一条件”是 UX 要求，不只是教学法**；四行推理会被拒绝。
4. **逻辑引擎与聊天人格要分离**：干净 brief + subagent 的做法，对应产品里的“规则/推理引擎”与“对话层”。
5. **考试模式是留存闭环**：上课教会，考试证明；报告让进步可见。

## 路线图

- Phase 1：共享盘面/notation/规则书 + 上课模式（当前）。
- Phase 2：claim 捕获 + 审计引擎 + 判定词表（考试模式）。
- Phase 3：报告、错题 drill、每日挑战、可分享 transcript。
- Phase 4：提示阶梯个性化、错误类型学。

## 指标

- 单步有效率；GAP 分类；提示使用率；notation 错误/局；解题时长；复访率；报告分享率。
